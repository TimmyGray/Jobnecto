# Converging: narrow and decide

Load this only once divergence is spent. Keep it separate from generating. Premature judgment kills good ideas.

**The stance still holds.** In Facilitator mode you structure the convergence and the **user** judges; never rank for them. In Creative Partner mode you weigh in too, with authorship logged. In "Ideate for me" you converge yourself and show the result.

## How to run it

1. **Reflect the field back.** Pull the live candidates from the session log, including odd and buried ones, so there is a concrete set on the table.
2. **Pick ONE move** that fits the decision and name it. Don't hand the user a menu of methods.

| Move | Use when |
|---|---|
| **Affinity clustering** | Many scattered ideas. Group them into named themes and surface the through-line. Often the right *first* move. |
| **Impact / Effort** | The goal is action. Place candidates on a 2×2 and take high-impact/low-effort first. For Jobnecto, estimate effort against the existing Clean Architecture layers and the Angular SPA. |
| **NUF test** | Novelty matters. Score each idea New / Useful / Feasible on a 1–10 scale. The totals expose quiet winners and dazzling-but-doomed ideas. |
| **Forced ranking** | You just need a top-N. No ties. |
| **PMI** | One strong candidate needs pressure-testing: Plus / Minus / Interesting, then judge. |
| **MoSCoW** | Scoping a build: Must / Should / Could / Won't-this-time. |

3. Chaining two or three moves is fine (e.g. cluster, then score the clusters). More is over-processing.
4. Log each surviving direction as a `[decision]` entry with its reasoning.
5. Go back to **Wrap-up** in `SKILL.md`. Only wrap-up sets `status: complete`.
