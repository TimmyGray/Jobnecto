## 2. What Went Well

### Previous-story intelligence actually carried forward
Each story picked up the last one's decisions instead of re-deciding them. 2.1's Decision Record said "promote the toast host when a second page needs it", and 2.4 did it. 2.2's `nextCursor` resolved the `PageCursor` nullability deferral from 1.6. The route-ordering test gap from 2.1 was closed in 2.2.

### Self-review caught real bugs before merge
These would have shipped:
- Salary sent as a JSON string, and skills errors never rendering inline (2.1).

2.3 and 2.4 ran every status-code claim against a throwaway Postgres. One claimed bug was **disproved** this way (the 2.2 "cursor row edited" item, `deferred-work.md`) rather than being "fixed" for nothing.

2.4 ran mutation checks and found vacuous tests (for example "Save disabled while deleting" on a pristine form). Coverage never dipped below 97% lines.

### Post-merge docs cadence recovered
After 2.1's late docs (see §3), 2.2-2.4 each got their own docs PR within minutes of the merge (#98, #100, #102).

## 3. What Hurt

### Lesson 1: The mandatory PR review was skipped for half the epic
AGENTS.md (*Mandatory comprehensive PR review workflow*) requires the adversarial review on every PR. 2.1 had a full RV (Blind Hunter / Edge Case Hunter / Acceptance Auditor). 2.2 had an RV with a different lens set. **2.3 and 2.4 have no `## PR Review (RV)` section** and were merged **2 minutes after their feat commits** (`e09d033`→`d6d13ea`, `497b11f`→`0b50e46`). Their self-reviews were good: 4 lenses and 3 lenses. But a self-review is not the independent review AGENTS.md requires, and the merges were self-merges.

### Lesson 2: Nothing was verified in a real browser
2.2's manual smoke test was not run (Task 7 is left `[ ]`, honestly). 2.3 and 2.4 skipped the browser half because Claude-in-Chrome was not connected. Native `<dialog>` behaviour (focus trap, Escape, backdrop), skeleton/card layout parity and the shell toast are all verified **only against jsdom stubs**. A real-browser pass was finally run on 2026-10-26 (§10). It confirmed the dialog and list behaviour, but it also found a **High** create-contract bug (B1) that every jsdom test and live-API check had missed, because none of them omitted the optional fields.

### Lesson 3: The backend coverage gate was skipped three times for a tooling reason
2.2, 2.3 and 2.4 each record "backend coverage gate not re-run — python not on PATH". That claim was false. On 2026-10-26 `python` resolved to `C:\Python314\python.exe` in both Git Bash and PowerShell. Only `python3` fails, and only in Git Bash, where it hits the Microsoft Store stub. Backend code barely changed after 2.1, so the actual risk was low. The process risk is not: a CI-enforced gate was skipped locally three times in a row.

### Lesson 4: The same bug classes were re-derived in every story
`deferred-work.md` and every story's Review Findings show the same classes repeating:
- **Focus loss:** 2.2 (5 fixes), 2.3 (retry; 403/404 on save deferred), 2.4 (403/404 fixed; list after delete deferred). The root cause is named in 2.4: *the app shell has no post-navigation focus management*.
- **In-flight races and cancellation:** 2.1 (list/create race, no cancel on destroy), 2.2 (double retry), 2.3 (save vs route change; response wiping in-flight edits), 2.4 (busy flag reset before navigation). Each story re-derived `takeUntilDestroyed` / cancel-on-route-change / hold-busy-until-navigation.
- **Server data silently lost:** 2.1 (skills, then the same class for locations/languages, found only in RV), 2.3 (legacy half-filled language rows, deferred).

None of this reached `agent-learnings.md`. The file has had no entries since 2026-05-23, although 2.1, 2.3 and 2.4 all had post-implementation test failures that the self-improvement protocol counts as triggers.

### Lesson 5: Story plans contained errors the dev had to correct
- 2.1 assumed 127 `Location` members; there are 122.
- 2.2 planned a widget `totalCount` input that nothing needed.
- 2.3's Trap 2 prescribed the **wrong** reset order, and the first spec run caught it.
- The NFR10 mislabel in `epics.md` Story 2.1 AC3 (flagged in 2.1, systemic since 1.4) is **still uncorrected**.

### Lesson 6: An external advisory broke CI mid-epic
A new NuGet advisory (GHSA-846f-f764-76mx / GHSA-2fmv-rv2c-59x7, transitive via EF Core Design) failed every branch's `--warnaserror` build. It was fixed by pinning `System.Security.Cryptography.Pkcs` 9.0.21 (PR #97, `ce9f214`). This is the same class of break as PR #83 (Swashbuckle, NU1903). Nothing watches for these between feature PRs.

### Lesson 7: 2.1's post-merge docs ran 23 days late
2.1 merged on 09-28. Its docs commit `a183991` was written on 10-21, on the 2.2 branch, with no separate PR. This repeats the slip that `agent-learnings.md` 2026-05-09 ("Run mandatory post-merge docs workflow immediately") already covers. It recovered for 2.2-2.4.

## 8. Proposed `agent-learnings.md` Entries

These are **proposals**, not yet added. Format per `.github/instructions/self-improvement.instructions.md`.

```
### 2026-10-26 - Hold the busy flag until a post-success navigation settles

**Trigger:** Review finding
**Context:** Story 2.4 `ResumeDetailPage` delete flow (`frontend/src/pages/resume-detail/resume-detail.page.ts`), and the same shape in Story 2.5's create flow.
**Wrong action:** I reset `deleting` in the HTTP subscription (`finalize` / `next`) and then called `router.navigate`, so Save and Delete were re-enabled for a résumé that no longer existed while the lazy route loaded.
**Root cause:** I treated "request finished" as "action finished". When the success path navigates, the action ends when the navigation settles.
**Correct behavior:** When success navigates away, keep the busy signal true until `router.navigate(...)` resolves. Show the toast in `.then(...)`. Reset busy only when the navigation is rejected or on error.
**Pattern / trigger:** Any Angular page whose success handler calls `router.navigate` after a mutating request.
**Generalize?** Yes
```

```
### 2026-10-26 - A component-state assertion is not proof the DOM shows it

**Trigger:** Review finding
**Context:** Story 2.1 PR review, `ResumeFormComponent` language-row server errors (`frontend/src/widgets/resume-form/resume-form.ts`).
**Wrong action:** I asserted that `setErrors()` had put the error on the dynamically added `FormArray` control. The test passed while the real UI showed nothing, because the next render wiped the error and the fallback banner needed `markForCheck()`.
**Root cause:** I tested the model, not the rendered output, for a behaviour the user only experiences through the DOM.
**Correct behavior:** For every user-visible error/state, assert on the rendered DOM (text present, `aria-describedby` wired) after `fixture.detectChanges()`, and mutation-check it: remove the production line and confirm the test fails.
**Pattern / trigger:** Tests for server-error mapping, dynamic `FormArray` rows, OnPush components updated outside an input change.
**Generalize?** Yes
```

```
### 2026-10-26 - Never skip a CI-enforced gate locally because of a missing tool

**Trigger:** Process slip
**Context:** Stories 2.2, 2.3, 2.4 Debug Logs: "backend coverage gate not re-run — python not on PATH".
**Wrong action:** I recorded the gate as skipped and moved the story to review three stories in a row.
**Root cause:** I treated a local tooling gap as a reason to skip the gate instead of resolving the tool.
**Correct behavior:** Resolve the tool first. On this machine `python` works in both shells, while `python3` hits the Microsoft Store stub in Git Bash. Run the gate, and record its output. If it truly can't run, the story is not ready for review. Say so and stop.
**Pattern / trigger:** Any verification step listed in the story's final task that fails for an environmental reason.
**Generalize?** Yes
```
