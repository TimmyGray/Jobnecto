## 2. What Went Well

### DB-backed uniqueness constraint — correct implementation
One non-deleted cover letter per user per vacancy is enforced by `IX_CoverLetter_UserId_VacancyId WHERE IsDeleted = false`. The 409 comes from `DbUpdateException` catch, not a pre-existence check, matching the cover letter template pattern and closing the concurrent-create race. This is the right implementation.

### `ICoverLetterRepository` — legitimate specialization
Introduced per Decision 3 reasoning: ordering by `CreatedAt DESC` (not `UpdatedAt`) and a JOIN to `Vacancies` for the list item `vacancyTitle` cannot be achieved via the generic `BaseRepository<T>.GetAsync`. The specialized interface has two concrete methods with clear purposes — not symmetry for symmetry's sake.

### `IgnoreQueryFilters()` on vacancy side of detail query (5.3)
Soft-deleted vacancies would disappear from the JOIN result without `IgnoreQueryFilters()`, making cover letter detail unreachable after a vacancy soft-delete. The implementation handled this edge case proactively.

### VacancyId immutability — enforced by omission, not by ignoring
Not including `VacancyId` in `UpdateCoverLetterCommand` is cleaner than accepting it and blanking it. No accidental mutation path exists.

### Cross-user coverage was already comprehensive pre-R.3
`CoverLettersApiTests.cs` was the most complete feature test file before Epic R ran — R.3's authorization suite built on it rather than starting from scratch.

## 3. Challenges and Lessons

### Lesson 1: Story artifact drift — third consecutive epic (FIXED)
All five Epic 5 story files had unchecked task checkboxes (`- [ ]`) and File Lists showing only the story file itself. This is Lesson 1 from Epic 3 retro and Lesson 1 from Epic 4 retro — never addressed.

**Fixed during this retro session:** All task checkboxes updated to `- [x]`; accurate File Lists added to all five stories based on actual codebase scan.

**Root cause:** No mandatory completion step enforces artifact updates before `Status: review` flip.

**Process fix (Option A adopted, Timmy decision):** Dev agent must update task checkboxes and file list in the story file before marking a story `Status: review`. This is added to AGENTS.md as a mandatory story completion step.

### Lesson 2: No test counts or review findings recorded
Zero debug log references in any Epic 5 story. No code review finding sections. Either reviews were not run on Epic 5, or findings were not recorded. Contrast with Epic R where every story had test counts, debug output, and review findings.

**Note:** Cannot retroactively reconstruct test counts or review findings for Epic 5 accurately. Recorded as "not documented."

### Lesson 3: Cursor semantics naming confusion
`lastSeenUpdatedAt` carries `createdAt` values for the cover letters list endpoint. The shared pagination envelope uses a single timestamp field name regardless of the sort key. Documented explicitly in Dev Notes but non-obvious to anyone reading the API contract.

**Action:** Add a note to the `CoverLettersController` list endpoint's OpenAPI XML comment or `ProducesResponseType` context to clarify the cursor field semantics for this endpoint.

### Lesson 4: `templateId` product decision not in change log
The original Epic 5 plan included an optional `templateId` (reference to a cover letter template). This was dropped per product decision — content is user-injected directly. The drop was documented in Story 5.1 Completion Notes but never recorded as a formal product decision or change log entry.
